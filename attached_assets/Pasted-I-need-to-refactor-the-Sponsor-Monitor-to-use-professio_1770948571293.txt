Step 3: Refactor the Daily Cron Job
Replace the simple diff logic with this new flow:

A. Scrape the CSV URL:
   - Fetch https://www.gov.uk/government/publications/register-of-licensed-sponsors-workers
   - Use cheerio to find the anchor tag linking to assets.publishing.service.gov.uk ending in .csv
   - Download that specific file (the URL changes daily)

B. Ingest and Fingerprint:
   - Parse the CSV.
   - For each row, generate: fingerprint = normalize(name) + "|" + normalize(city) + "|" + route
   - Store in a temporary array: todaysRecords

C. Reconciliation Logic:
   - Load all ACTIVE records from sponsor_canonical into memory as a Map keyed by fingerprint.
   
   Process todaysRecords:
   - If fingerprint exists in Map: Update last_seen to today, reset consecutive_misses to 0. Check if type_rating changed (A to B = DOWNGRADE event, B to A = UPGRADE event). Update current_name if it differs (name correction).
   - If fingerprint does NOT exist: Add to sponsor_canonical as new ACTIVE record with first_seen today. Log "NEW_LICENCE" event.

   Process missing records (in DB but not in todaysRecords):
   - For each missing record, increment consecutive_misses by 1.
   - If consecutive_misses == 1: This is first absence. Run "Rename Check":
     - Compare missing record's name against all NEW records added today (same city, same route).
     - Use string-similarity. If similarity > 0.85 (85%):
       - This is a RENAME. Update the fingerprint in sponsor_canonical to the new fingerprint.
       - Merge the records. Do NOT mark as NOT_LISTED.
       - Log "NAME_CHANGE" event.
     - If similarity < 0.85: Mark as potentially gone. Wait.
   - If consecutive_misses >= 2: Mark status as "NOT_LISTED". Log "REMOVED" event. Trigger notification alerts.

D. Cleanup:
   - Keep daily snapshots in sponsor_list for 90 days as before.
   - Keep canonical records forever (or archive after 2 years).
