Complete the Sponsor Monitor feature implementation by adding the hybrid notification services, security, and business logic limits. Follow these specific steps:

1. Messaging Services Setup
Install the twilio package. Create a new service file (e.g., server/services/messaging.ts).
In this file, export two functions:

sendSMS(phoneNumber, message): Use the existing Brevo SDK instance to send a transactional SMS. Set the sender name to "CheckByAI". Handle errors gracefully and return the message ID.
sendWhatsApp(phoneNumber, message): Initialize a Twilio client using process.env.TWILIO_ACCOUNT_SID and process.env.TWILIO_AUTH_TOKEN. Send the message using process.env.TWILIO_WHATSAPP_NUMBER. Handle errors gracefully.
2. Phone Number Encryption
Create a crypto utility file. Add a encryptPhone(phone) and decryptPhone(encryptedPhone) function using the aes-256-gcm algorithm. Use process.env.PHONE_ENCRYPTION_KEY as the secret.
Update the notification_preferences table interactions in your API:

Encrypt phone numbers before saving them to the database.
Decrypt phone numbers when retrieving them for the frontend UI.
Decrypt phone numbers when retrieving them to send notifications.
3. Wire Up Notification Dispatcher
Update the existing notifyAffectedUsers function in your notification dispatcher:

If the user has sms_enabled and sms_verified, call sendSMS with a concise version of the alert.
If the user has whatsapp_enabled and whatsapp_verified, call sendWhatsApp with the alert.
Log the provider message IDs to the notification_log table.
Ensure the existing email logic remains intact.
4. Activate Real Verification
Update the POST /api/notification-preferences/verify-phone endpoint:

Instead of logging the OTP to the console, actually send it.
If verifying for SMS, call sendSMS.
If verifying for WhatsApp, call sendWhatsApp.
5. Enforce Plan Limits
Update the POST /api/watches endpoint to check the user's plan limits before adding a watch.

Free Plan: Max 1 watch.
Starter Plan: Max 5 watches.
Pro Plan: Max 20 watches.
Unlimited Plan: Unlimited.
Return a 403 error with a specific message if the limit is reached.
6. Reliability & Duplicate Handling
Update the diff engine and snapshot storage logic to handle duplicate company names. Use a composite key of normalizedName + townCity to distinguish companies.
Update the daily Cron job to include retry logic: if the CSV download fails, retry up to 3 times with a delay.

7. Public Changes Page
Create a new public frontend route at /sponsor-changes.

This page requires no authentication.
Fetch and display the last 7 days of changes (Removals, Downgrades, Additions) grouped by date.
Add SEO headers for this page.
8. Admin Test Route
Create a backend endpoint POST /api/admin/sponsor-monitor/test (Admin only).

When called, simulate a detection cycle: create a fake "yesterday" snapshot, create a fake "today" snapshot with 1 removal and 1 downgrade.
Run the diff engine and trigger notifications for a test user to verify the whole pipeline works without waiting 24 hours.
