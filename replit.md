# COS Verification System

## Overview
This project is an AI-powered Certificate of Sponsorship (COS) verification system designed to detect fake or edited COS documents. It provides a user portal for document verification and an admin portal for managing trusted patterns. The system utilizes machine learning, including rule-based matching, vector similarity, and ML model inference, to ensure accurate authenticity assessments. Its primary goal is to offer a reliable tool to combat fraud in critical immigration documents. The project envisions becoming a leading solution for immigration document verification, ensuring compliance and security for individuals and organizations alike.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture
The system features a dual-portal design: an Admin Portal for managing genuine COS documents and a User Portal for submitting documents for AI verification. Verification results are classified as Genuine, Suspicious, or Fake, each accompanied by a confidence score.

**Frontend:**
- **Framework**: React with TypeScript
- **Styling**: Tailwind CSS with shadcn/ui
- **UI/UX Decisions**: Professional color scheme, adaptive color-changing result badges with gradient backgrounds and animations, mobile optimization with responsive design, and SEO-optimized pages with unique metadata and structured data.
- **Shared Layout (`PageLayout.tsx`)**: All pages use `PageLayout` for sticky nav + footer + page-transition animation. Props: `hideNav` (omit nav), `hideFooter` (omit footer), `darkNav` (dark-slate nav variant — `bg-slate-950/95`, `BrandLogo variant=dark`, slate-300/white link palette). `NavDropdown` accepts matching `dark` prop. The "Get Alerts" CTA in the nav is suppressed on `/pricing` to prevent a self-referential link. `SponsorMonitor` uses `<PageLayout darkNav>` — it has no custom nav/footer of its own. Route `/verify-cos` is an alias for `/dashboard` (renders `DashboardPage`).
- **3D Graphics**: Three.js with @react-three/fiber for an animated landing page.

**Backend:**
- **Runtime**: Node.js with Express
- **Database**: PostgreSQL with Drizzle ORM
- **PDF Processing**: Custom PDFAnalyzer for metadata extraction.
- **Verification Engine**: Rule-based forensic analysis, including producer matching, date consistency checks, XMP history analysis, and suspicious software detection.

**Key Features:**
- **User Portal**: File upload, real-time verification results with confidence scores, and detailed forensic analysis.
- **Admin Portal**: Management of trusted COS documents, system statistics dashboard, and role-based access control.
- **Authentication**: Database-backed user authentication with role-based access and session management, supporting Google OAuth and Email OTP verification. Admin login is OTP-only.
- **CoS Check Beta Gate**: CoS Check is in closed beta. The `cosCheckApproved` boolean field on the `users` table controls access. Anonymous and unapproved users see a gated screen (`COSDashboard.tsx`). Admins approve/revoke access via `PATCH /api/admin/users/:id/cos-approval` (visible in the Users tab with "CoS Beta" column + Approve/Revoke buttons). Approval sends a Resend email to the user.
- **Dynamic AI Knowledge Engine**: Trainable AI system allowing admins to add custom forensic rules and pattern-specific instructions, which are explicitly cited in AI analysis.
- **Human-in-the-Loop (HITL) Feedback**: Admins can override AI results, providing reasoning that trains the AI and prevents future errors.
- **Multi-AI Fallback System**: Automatic failover between AI providers (OpenAI → Claude → DeepSeek) ensures continuous document analysis. Centralized in `server/services/aiService.ts` with `createChatCompletion` (non-streaming) and `createChatCompletionWithFallback` (streaming). Graceful zero-provider handling returns 503. AI Digest headlines also use the fallback chain (no direct API calls).
- **Sponsor Licence Monitor**: Tracks changes in the UK Home Office Register of Licensed Sponsors using a 5-phase pipeline. **Architecture** (as of 2026-03-20): Phase 1 — `discoverCsvUrl()` + `ensureTodaysArchive()` downloads CSV to disk (`data/archives/`), validates with qsv (structural check + 100,000-record hard floor), registers in `csv_archive` table. Phase 2 — `runCsvDiff()` diffs yesterday's vs today's fingerprinted CSV using the `csvdiff` Go binary, outputs `{Additions, Deletions, Modifications}`. Phase 3 — `applyStateMachine()` processes the diff through a 4-state model: `NEWLY_GRANTED` (new licence) → `ACTIVE` (confirmed) → `GRACE_PERIOD` (absent day 1) → `REMOVED_REVOKED` (confirmed removed, ≥2 misses). Phase 4 — `notifyAffectedUsers()` dispatches per change type with `notification_log` FK integrity via `.returning()` from `batchedInsertChanges()`. Phase 5 — daily digest + `monitor_job_runs` audit. **Database tables**: `sponsor_canonical` (per-company state), `csv_archive` (daily CSV registry), `diff_results` (diff audit), `company_watches`, `sponsor_changes`, `notification_preferences`, `notification_log`, `monitor_job_runs`. `sponsor_list` table DEPRECATED 2026-03-20; DROP scheduled 2026-04-20. **ChangeTypes**: `NEW_LICENCE`, `RE_ACTIVATED`, `REMOVED_REVOKED`, `GRACE_PERIOD`, `UPGRADED`, `DOWNGRADED`, `ROUTE_CHANGE`, `NAME_CHANGE` (last one non-alertable). Watch limits: free=1, starter=2, pro=5, unlimited=-1, enterprise=-1. **Reliability**: Single daily cron 00:30 UTC Mon-Fri + DB idempotency check (no backup cron, no startup catch-up — superseded by idempotency). Request-triggered middleware fires on API requests after 01:00 UTC if today's job hasn't run. DB operations wrapped in `withRetry`. Binary tools: qsv (Rust, dathere/qsv) + csvdiff (Go, aswinkarthik/csvdiff) — qsv degrades gracefully if missing; csvdiff missing = hard failure.
- **Multi-Channel Notifications**: Supports email (Resend), SMS (Brevo), and WhatsApp (Twilio) with encrypted phone numbers (AES-256-GCM, `enc:` prefix) and phone verification via OTP.
- **Product Separation**: CoS Check and Notification Engine are separate products with separate pricing pages. `/pricing` shows Notification Engine only (primary product). `/cos-pricing` shows CoS Check plans only. CoS Check has 4 plans (Starter, Pro, Unlimited, Master). Notification Engine has 2 plans (Starter £24.99/mo with 2 companies, Pro £49.99/mo with 5 companies and 5 CoS checks/month). Bundle benefits: Unlimited Monthly (£99.99/mo) includes 10-company notification watchlist; Master Package (£99.99 one-time) includes 5-company notifications for 3 months. Backend uses packageTypes: notification_starter, notification_pro (distinct from CoS starter, pro).
- **Tiered Alert System**: Centralized in `server/utils/tierConfig.ts`. SubscriptionStatus values: 'free', 'starter', 'pro', 'unlimited', 'enterprise' (1:1 mapping to tiers, no legacy aliasing). Pricing: Starter=£24.99/mo (£239.99/yr), Pro=£49.99/mo (£479.99/yr), Unlimited=£99.99/mo. FREE=next morning 8am UTC, STARTER=same-day 6pm UTC, PRO/UNLIMITED/ENTERPRISE=immediate. Channel gating: Starter gets email+WhatsApp, Pro gets email+WhatsApp+SMS, Unlimited gets all channels. Hourly cron processes delayed notification queue.
- **Verification Receipt System**: Each verification generates a unique Receipt ID, Document Hash, and Integrity Hash for audit trails, ensuring tamper-proof verification while documents are immediately deleted after processing.
- **Security Hardening**: Includes measures like OTP-only admin login, file upload limits (10MB max, PDF only), same-origin CORS, secure session cookies, generic error responses, and robust security headers. Rate limiting via `express-rate-limit`: `authLimiter` (10 req/15min) on login, `otpLimiter` (5 req/15min) on all OTP send/verify endpoints, `verifyLimiter` (10 req/hour) on `/api/verify` to prevent AI inference cost abuse. Stripe webhook signature verification uses raw request body (`req.rawBody` captured via `express.json` verify callback). DB-backed Stripe idempotency via `processed_checkouts` table (survives server restarts). React `ErrorBoundary` class component wraps the `<Router>` to prevent blank white screens. Critical multi-step writes (checkout fulfillment, credit deduction + verification result) wrapped in `db.transaction()` with `withRetry()` for Neon connection resilience. Indexes on `users.stripeCustomerId`, `users.role`, `paid_submissions.stripeSessionId/reviewStatus/email`, `expert_requests.status/userId/stripeSessionId`. All previously-silent `catch {}` blocks now log errors via `console.error`. **Security headers**: CSP (Content-Security-Policy with strict prod/relaxed dev variants), HSTS (production only, 1yr), Permissions-Policy (camera/mic/geo disabled). **Startup env validation**: Server checks for 7 critical env vars (`DATABASE_URL`, `SESSION_SECRET`, `ADMIN_EMAIL`, `PHONE_ENCRYPTION_KEY`, `IP_HASH_SALT`, `CHECKOUT_HMAC_SECRET`, `DIGEST_SIGNING_KEY`) and exits with error in production if any are missing. **CAPTCHA**: Cloudflare Turnstile on OTP send endpoint — backend verifies token against Turnstile API when `TURNSTILE_SECRET_KEY` env var is set; gracefully skipped in dev without the key. Frontend widget in `login.tsx` using `@marsidev/react-turnstile` controlled by `VITE_TURNSTILE_SITE_KEY`. **Zod validation**: Added schema validation on `/api/watches` (POST), `/api/notification-preferences` (PUT), `/api/admin/users/:id/limit` (PATCH), `/api/admin/trust-producer` (POST). **urlencoded parser**: Changed to `extended: false` to prevent prototype pollution via nested object deserialization. **multer**: Updated to 2.1.0 to patch 2 HIGH-severity DoS CVEs. **RLS status**: No PostgreSQL Row Level Security policies exist at DB level — protection is application-layer only via `isAuthenticated`/`isAdmin` middleware and userId ownership checks on all routes. Full DB-level RLS is an outstanding hardening item for a future migration.
- **Data Protection Policy**: Adheres to UK GDPR by processing only document metadata, permanently deleting original documents post-verification, and offering users data erasure rights.
- **Daily Digest System**: AI-generated headlines from sponsor register changes using the multi-AI fallback chain (OpenAI → Claude → DeepSeek). Database tables: `daily_digest` (headline variants, counts, HMAC-signed), `ai_generation_logs` (audit trail). Cron generates after detecting changes. Deterministic fallback when API unavailable. Frontend `LandingDigest.tsx` component with animated counters and "Updated {formattedDate}" caption on Live Data badge. **`SponsorMonitor.tsx` live data**: `StickyAlertBanner` (top of page) fetches `/api/daily-digest/current` and hides when `counts.removed === 0`, shows real revocation count + date otherwise. `ProofBar` uses same queryKey (React Query deduplication) for active sponsors, changes summary and last-check date. `SocialProof` fetches `/api/sponsor-changes` and shows the most-recent REMOVED/REMOVED_REVOKED/DOWNGRADED event; hides when no qualifying 7-day changes exist.
